# Project notes

- Read `README.md` for the product and for install/setup, `docs/operations.md` for day-to-day commands, Herdr ownership, and verification, and `docs/implementation-contract.md` for the implemented API. Storage backend, the node-failure loss window, and live Herdr installation remain open.
- `adm` is the Rust CLI. The runner and terminal are the npm workspaces `@adm/runner` and `@adm/terminal`. Repository catalog code is `packages/repositories`. The workspace image is `image/Dockerfile` (`adm-dev:0.1.0`).
- Tests: `cargo test`, `npm test`, and `npm run test:repositories`. The repository test needs `/dev/fuse` and `artifact-fs` on `PATH` (pin in `packages/repositories/ARTIFACTFS`). It skips without `/dev/fuse` and fails if the binary is missing while FUSE is present.
- `.github/workflows/build.yml` verifies the CLI, runner, and terminal, then publishes `linux/amd64` `adm`, `adm-repositories`, and the workspace image to GHCR. `main` tags the image `latest` and `sha-<commit>`; a `v*` tag also publishes that version and a GitHub release. Markdown-only pushes and pull requests skip the workflow. FUSE tests stay outside this workflow. The release CLI still needs the checkout (`--project-dir` or `ADM_PROJECT_DIR` when the binary was not built there).
- `cargo clippy --all-targets -- -D warnings` and `npm run check` check the implementations. `npm run test:image -- IMAGE` runs isolated unprivileged Docker/Git/Chromium checks. `ADM_LIVE_CLUSTER=1 npm run test:cluster-contract` checks real owned namespace lifecycle and server-side manifest validation. The full `test:cluster` additionally needs `ADM_LIVE_IMAGE` cached on every schedulable node; it never installs node helpers.
- Agent creation requires an explicit `--model PROVIDER/MODEL_ID`, or `--no-agent` for a shell-only workspace. The lazy catalog is opt-in through `--catalog`; ordinary workspaces have a writable `/repos` without a FUSE sidecar.
- Provider failures persist in runner status/history. `/resume` is explicit and deduplicated; after tools have run, reconcile their effects with a deliberate follow-up. Do not add provider/billing or environment fallback.
- `adm herdr watch --socket "$HERDR_SOCKET_PATH"` runs inside the owning Herdr session and journals received explicit close events before cleanup. Never infer deletion from missing spaces or a lost connection. The current Herdr API has no replay cursor for missed events; supervise the watcher and keep this limitation visible.
- The target is a homelab CLI/workspace service integrated with Herdr and Kubernetes. Workspace identity must be independent of the current runtime and physical node.
- Confirmed persistence scope: repository work and agent history; installed tools are ephemeral or supplied by the base image. Some recent work loss after rare unexpected node failure is acceptable; the exact window is unchosen.
- Every development workspace has private writable files and Git state, regardless of branch names. Share immutable upstream data only. Coding agents have no access to other workspaces; bots may use explicitly permitted monitoring/prompting interfaces without repository, shell, or general cross-workspace access.
- Agents must execute unattended independently of SSH, CLI, and terminal connections. Nick connects from MacBooks to Herdr on a long-running Debian management box.
- Manual Herdr space removal destroys its runtime and private files and cancels its owned agents, goals, loops, and pending work. Recovery must not recreate deliberately deleted workspaces. Conversation retention remains open; configurability is an acceptable proposal.
- User-facing coding and bot conversations belong in Herdr with a Pi-style terminal interface. Browser automation and access to development sites/ports from MacBooks are required.
- Bots are a separate non-coding role: no repository access or coding tools, including indirectly through Code Mode. They can monitor/prompt explicitly permitted coding agents and maintain durable goals/loops. Bot-to-space and bot-to-agent assignments remain open.
- Bot model output is hidden by default; only explicit `sendMessage` calls publish AI-authored messages in its terminal conversation. Keep inspectable diagnostics separate from chat delivery.
- Nick uses Codex via Plus currently and is considering Claude. Keep providers/auth configurable; subscription compatibility, numeric budgets, and migration are not settled. No silent provider/billing fallback.
- Lazy GitHub repository access and storage efficiency on 256 GB nodes remain goals. The storage backend is still unchosen. The runner is Pi Durable 1.2.0 on the management host, distinct from ordinary Pi session files. Coding tools run in the workspace container.
- `docs/pi-durable-research.md` records the 1.2.0 findings. The terminal is an HTTP client, not native Pi RPC. Harness close and ordinary abort are not workspace destruction. SQLite WAL still needs a compatible filesystem and one owner; it is not a cross-node durability proof.
- Preserve the distinction between requirements and proposals. Do not turn candidate technologies or command syntax into settled decisions without evidence.
- Do not claim transparent process recovery or filesystem durability that has not been demonstrated end to end.
- Follow the home-level `AGENTS.md`. Keep using end-to-end tests for behavior changes.
