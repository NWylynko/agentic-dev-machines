# Layout

- `src/` — Rust `adm` CLI, the in-cluster lifecycle service (`adm lifecycle-serve`, `src/lifecycle.rs`) and the node failover sweep (`adm failover-serve`, `src/failover.rs`). Feature files: `repos.rs`/`repo_registry.rs` (GitHub repos), `connectors.rs` (MCP), `agents_file.rs`, `herdr.rs`, `update.rs`, `system_log.rs`, `lease.rs`, `workspaces.rs` (manifests).
- `packages/runner` (`@adm/runner`) — Pi Durable 1.2.0 runner in each workspace Pod, plus the authorities hosted in the lifecycle Deployment's `provider-auth` container: provider auth, GitHub (`github-authority.ts`), MCP connectors (`connector-authority.ts`), shared agents file.
- `packages/terminal` (`@adm/terminal`) — `adm attach`: pinned upstream Pi InteractiveMode through patched remote ports (`scripts/patch-pi-interactive.mjs`), projecting the Pod's Durable conversation. Owns no executor or local Pi session.
- `packages/repositories` — Go `adm-repositories` sidecar serving `/repos` over FUSE (ArtifactFS, pin in `ARTIFACTFS`), one `artifact-fs daemon` per opened repository.
- `image/Dockerfile` — five role images: `adm-control`, `adm-repositories`, `adm-workspace` (init), `adm-code` and `adm-bot` (both `FROM adm-workspace`).
- `deploy/lifecycle` — `adm-system` control plane manifests: `adm-lifecycle` and the stateless 2-replica `adm-failover` Deployment. Storage class `adm-replicated` (Longhorn, RWO, 3 replicas).

# Invariants

- All coding and bot execution runs in workspace Pods. The client is an access plane: each command opens its own `kubectl port-forward` and closes it; no host daemon. `adm start/serve/stop` start no host runner.
- Workspace identity is an immutable ID, independent of name, Pod and node. Destroy tombstones first; recovery never recreates a deleted workspace. Same-spec `adm create` retries keep the ID, volume and edits.
- Credentials: the operator token is only in Secret `adm-system/adm-lifecycle-token`, fetched into memory. Pods get a projected SA token (audience `adm-lifecycle`, bound to the Pod UID) and nothing broader. Provider refresh tokens, the GitHub token (`github.json`), and MCP grants stay on the lifecycle PVC; Pods fetch short-lived values per request through `/v1/runtime/...` routes. Never log tokens. Never store keys in ADM config, env files or service units.
- Bots: no repository, shell or coding tools (including via Code Mode). They control coding workspaces by immutable ID through lifecycle APIs, and publish text only through `sendMessage`. Bot routes for repos, agents file and resources answer 403.
- Fencing: runtimes hold a 300 s lease from the lifecycle, renewed every 10 s. Only a rejection (4xx, or a renewal with a changed fence) or the lease's own deadline fences a runtime: it closes work, fails health, and the Pod restarts. An unreachable lifecycle (5xx, refused, timeout) only pauses new admissions, so lifecycle outages under 5 min stop no workspace. A claim from a new Pod UID while the holder's Pod still exists gets 403 `held by another pod`; once the holder's Pod is gone (failover, eviction, `kubectl delete pod`) the lifecycle revokes the old holder (`revoke_lease_of_moved_workspace`) and grants the claim at once, and the old holder's next renewal gets 403. Lifecycle fencing is in memory (`lease::verify`, renewal every 5 s). A transport failure is not lease loss — return 503, never 4xx, for infrastructure errors or runners fence themselves.
- Fail loudly: no provider, billing or environment fallback. Provider errors stay visible until an explicit retry. `/resume` after tool effects requires a deliberate follow-up.
- Early alpha: no legacy migration or backwards-compatibility layers, except that `adm update` must keep working from the currently released client (see Releases).
- Don't claim recovery or durability that hasn't been demonstrated end to end. Keep requirements and proposals distinct. Still unvalidated live: native macOS/arm64, cross-node recovery and the node-failure loss window, live Herdr delivery, shared-provider sessions.

# Features (current behavior)

- **Repositories.** `adm repos login` stores the cluster GitHub login (gh device flow inside provider-auth). `adm repos clone|list|remove OWNER/REPO` keep one registry in the lifecycle's `workspaces.sqlite`; every coding workspace sees registered repos lazily in `/repos` unless `--no-repositories`. Each repo has one shared read-only base on the `adm-repository-bases` RWX claim. `adm create --repo OWNER/REPO [--branch B [--base REF]]` prepares a checkout; `--new-repo OWNER/REPO` creates an empty private repo (one empty commit on `main`). In Pods, `git`/`gh` authenticate through `image/adm-git-credential` and `image/adm-gh`; an explicit `GH_TOKEN` wins.
- **Providers.** `adm login/logout PROVIDER`, one shared account per provider. Credentials refresh proactively 10 min before expiry; invalid_grant/400/401 is permanent and shows `login_expired` with `run adm login X`. `adm doctor` has a Providers section. The model catalog bounds each provider at 10 s, so one broken login never blocks the others.
- **MCP connectors.** `adm mcp add|login|logout|remove|list`, installation-wide; sign-in also accepts a pasted redirect URL for remote devices. Pods reconcile the catalog before each turn.
- **Built-in browser.** Pod coding workspaces (never bots) get the pinned `@playwright/mcp` over stdio (`packages/runner/src/browser.ts`, started at open with system chromium, `--headless --isolated --no-sandbox`, output in `/workspace/.adm/browser`; `ADM_PLAYWRIGHT_MCP_CLI`/`ADM_BROWSER_CHROMIUM` override the paths for tests). Tools use the connectors' MCP-to-tool path (`defineMcpTool`); a dead server restarts at the next turn and never fails the workspace; state is `browser` in status and runtime-status.
- **Shared agents file.** `adm agents-file` edits one installation document (revisioned, 409 on conflict), prepended to repository `AGENTS.md` on each coding turn. Bots never get it.
- **Claude Code.** `adm claude NAME [create options]` creates the workspace if missing (a bare `adm claude NAME` never creates; spec options go through create admission), then `kubectl exec -it … -- adm-claude attach`. `adm create --claude` does the same; `--no-attach`/no TTY runs `adm-claude start` and prints the record. `image/adm-claude` keeps one `claude --remote-control NAME` in tmux session `claude`, `CLAUDE_CONFIG_DIR=/workspace/.adm/claude/config`; the marker `/workspace/.adm/claude/enabled` makes the entrypoint restart it on Pod start (`adm-claude boot`). Runs alongside Pi in the same checkout, unfenced. Remote Control needs a full claude.ai login (setup-token is refused — `research/claude-code/README.md`); login is per workspace until shared `adm login claude` lands. MCP connectors reach Claude through `--mcp-config /workspace/.adm/claude/mcp.json` (rewritten on each start/attach by `image/adm-claude-mcp config`) with `headersHelper: adm-claude-mcp headers` fetching a short-lived token per connection; connectors added while Claude runs need a Claude restart. Test: `image/claude-mcp.test.mjs` drives the host's real `claude -p` against a fake Anthropic API (`ENABLE_TOOL_SEARCH=false` so MCP tools are offered directly); it skips without `claude` on PATH.
- **Shells.** zsh with pinned Oh My Zsh; `~/.zshrc` symlinks to `/workspace/.adm/zsh/.zshrc` on the private volume. `adm shell NAME --manage` adds a relay for status/history/prompt/abort. `adm exec` and `shell -- CMD` stay non-interactive.
- **Ports and browser.** `adm port NAME PORT` binds loopback; `--lan` binds `0.0.0.0` with no auth while the command runs. `adm browser NAME URL --screenshot PATH` writes PATH on the client.
- **Herdr.** `adm herdr bind` routes panes per device; Herdr 0.9 reads `config.toml` only at start or `herdr server reload-config`, so ADM reloads and fails if not `applied`. `adm herdr watch` is opt-in close cleanup; stock Herdr has no event replay, so never infer deletion from missing spaces.
- **Event streams.** `/events` sends `: keepalive` every 15 s; the terminal treats three silent intervals as a drop, logs to `$XDG_STATE_HOME/adm/terminal.log`, and reconnects. A stopping runner answers 503 `RUNNER_STOPPING` with `connection: close`.
- **Runtime status.** `GET .../runtime-status` is unauthenticated (NetworkPolicy limits port 7432) and must never call `modelCatalog()` — that goes through provider-auth and took ~4 s per row live.
- **Node failure.** The `adm-failover` Deployment (`src/failover.rs`, 2 replicas on different nodes, no PVC, no lock, idempotent) force-deletes ADM workspace Pods and the lifecycle Pod on a node NotReady for 180 s, then deletes that node's ADM VolumeAttachments (PV claimed from the lifecycle namespace or an `app.kubernetes.io/managed-by=adm` namespace) so RWO volumes attach elsewhere without the ~6 min detach wait. The lifecycle runs no failover loop and has no node or Pod-delete RBAC. Logs: `adm system-log --service failover` (every action names workspace ID or `adm-lifecycle`, node, PV, seconds NotReady). A partitioned-but-alive runner keeps working until its lease runs out or its next renewal is refused after the move. Workspaces on healthy nodes keep running through a lifecycle move of up to 5 min. When the lifecycle is unreachable, `adm list` and `adm doctor` explain why from the kubeconfig (`diagnose_unreachable_lifecycle` in `src/diagnostics.rs`: lifecycle Pod on a NotReady node, not ready containers, unscheduled); `adm doctor` reports a failed port-forward in its Lifecycle section instead of exiting. The live power-off test is not yet run: procedure in `docs/node-failover.md`.

# Tests

- `cargo test`, `npm test`, `npm run test:repositories` (needs `/dev/fuse` and `artifact-fs` on `PATH`; skips without FUSE, fails if FUSE exists but the binary is missing). Lint: `cargo clippy --all-targets -- -D warnings`, `npm run check`. CLI shell fixtures need zsh.
- CI uses newer stable Rust than local; reproduce lint failures with CI's toolchain (`cargo +<version> clippy ...`).
- `tests/cli.rs` and `tests/lifecycle.rs` drive the real binary against a fake kubectl (`FAKE_KUBECTL`). Its shared files are written by atomic rename via `put()` and read-modify-write under the `locked()` flock — never hold that lock across blocking waits. Every invocation is logged to `kubectl-invocations`; lifecycle stderr goes to `service.log`. Tests serving a fake authority on 127.0.0.1:7434 hold `PROVIDER_AUTHORITY_PORT`.
- Runtime identities are cached by token hash for up to 60 s, so a new Pod identity in a test needs a new token string. A Lease tampered with from outside is noticed within one renewal period: wait for `/health` 503 before asserting rejections.
- Runner tests: register `t.after` cleanup **before** starting anything, as one hook that stops the runner before its control server (`t.after` is FIFO), or a runner that fails startup hangs the whole file. Lease length comes from the fake lifecycle's `expiresAt`, but renewal runs every 10 s with no override, so outage tests wait for real renewals (a renewal-failure stderr line marks each); the TASK-91 outage test takes ~40 s. Reproduce intermittent hangs with `node scripts/stress-test.mjs FILE --name PATTERN --runs N --parallel 2 --deadline S`.
- `packages/runner/test/connectors.test.mjs` and `github-login.test.mjs` run the real `adm` binary (`ADM_BIN`, default `target/debug/adm`). Terminal PTY tests render the screen with `@xterm/headless` (200 rows), because raw PTY output keeps text Pi later removed.
- `packages/runner/test/browser.test.mjs` skips (with a message) when no chromium or `@playwright/mcp` is on the host.
- Image smoke: `npm run test:image -- IMAGE ROLE`, `npm run test:image:full -- IMAGE`. Live: `ADM_LIVE_CLUSTER=1 npm run test:cluster-contract`, `npm run test:cluster` (needs `ADM_LIVE_IMAGE`).
- `kubectl` gotcha: a test Pod with `nodeName` skips the scheduler, so a `WaitForFirstConsumer` claim never binds; use a `kubernetes.io/hostname` nodeSelector.

# Debugging the live cluster

- The homelab cluster is only for testing ADM. Read logs with `adm system-log [--service provider-auth] [--since 6h] [--follow]` (merges the `lifecycle` and `provider-auth` containers). New cluster services go in `ADM_SYSTEM_LOG_SERVICES` in `src/system_log.rs`. provider-auth logs one JSON line per event.
- Deploy an unreleased build to verify a ticket before Nick pushes `main`: build and push each role to ttl.sh — `for role in adm-control adm-repositories adm-workspace adm-code adm-bot; do docker build --platform linux/amd64 -f image/Dockerfile --target "$role" -t "ttl.sh/$role-<sha>:24h" . && docker push "ttl.sh/$role-<sha>:24h"; done`. Make a release dir outside the repo with `VERSION` (`dev-<sha>`), `CONTROL_IMAGE`, `REPOSITORIES_IMAGE`, `WORKSPACE_IMAGE`, `CODE_IMAGE`, `BOT_IMAGE` and a `deploy` symlink to the checkout's `deploy/`, then `cargo build --release --bin adm && adm --state-dir T --kubeconfig <kubeconfig> --lifecycle-namespace adm-system --project-dir <release dir> __update-services` with temporary `XDG_*` dirs. Only the lifecycle Pod is replaced. Publish a real release within 24 h or the controller image expires.

# Releases and updates

- Every green `main` build publishes a `sha-<commit>` GitHub release and marks it latest; `v*` tags publish pinned releases without promoting latest. Markdown-only pushes skip CI. FUSE tests are not in CI.
- `install.sh` installs checksum-addressed releases under `$XDG_DATA_HOME/adm/install`, commands in `~/.local/bin`. Release bundles carry the five `*_IMAGE` files.
- `adm update` runs the `install.sh` embedded in the **installed** client (`include_str!` in `src/update.rs`), so renaming a release file breaks every older client — tests only cover new client against new release. Fix a stuck machine by reinstalling from `main` with `sh -s -- --no-setup`, then `adm update`.
- `adm update` opens a maintenance window that every runtime must acknowledge before the controller is replaced; failures after `extend` cancel the window (`$STATE/update-maintenance.json` holds its ID). Retrying the lifecycle API on connection errors after rollout is the normal path. Only `adm update --workspace NAME` changes a running workspace's images; saved role defaults advance only within the release's image repository.
