# Review of the initial implementation

Baseline: `ee787a3`; reviewed commit: `a55d15f`. Independent standards and specification reviews examined `git diff ee787a3...HEAD` against repository conventions, the README, and the implementation contract. A separate audit checked the eight numbered validation workflows against actual source and executed evidence.

## Standards

- The SSE pump silently ended streams when history access failed. This conflicts with the requirements for complete logging and visible failures. The follow-up change records the workspace ID, cursor, and bounded error on stderr and sends a safe SSE error event before closing.
- Model-authored loops accepted a wider range of intervals and timestamps than the HTTP API. This is a possible duplicated-validation smell with a real behavior mismatch. The follow-up consolidates schedule validation so model tools cannot bypass API limits.

Two findings; the most consequential Standards finding was inconsistent schedule validation.

## Spec

- The contract permits setting a cancelled loop back to `active`, but the implementation only changed its record. After the old task terminated, the reactivated loop could remain unscheduled. A regression must prove that it executes again, including after restart, without creating duplicate active tasks.
- Loop delivery submitted directly to the conversation, bypassing the workspace admission check used by HTTP and bot prompts. That leaves a race against deletion even though the contract requires tombstones to reject subsequent admissions. Delivery must share the same deletion boundary.

Two findings; the most consequential Spec finding was delivery bypassing deletion admission.

## Workflow evidence

The original eight workflows remain the completion boundary. Local CLI, Durable/SQLite, bot isolation, terminal, Git/FUSE and Docker image proofs do not establish cross-node durability or live account behavior. The existing validation report correctly distinguishes those scopes.

The audit also identified missing storage diagnostics in `adm doctor`, despite its public command promising them. The follow-up regression drives the real CLI through missing, node-local, and available classes, preserving an HTTP 503 runner error and proving diagnostics do not allocate a workspace. It passes after the change.

Disk allocation was previously not measured. The FUSE integration now records private state and Git allocation without traversing mounted views; see [the fixture measurements](storage-measurement.md). During that addition, a previously intermittent FUSE I/O failure recurred. A passing rerun does not resolve it; that fault is being investigated before the implementation can be considered stable.
